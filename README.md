# PII Redaction Tool

A reproducible Python pipeline that detects personally identifiable information in DOCX/PDF input and writes a separate redacted DOCX. It uses validated regular expressions, context-aware rules, and an optional spaCy NER adapter rather than an external paid API.

## Important scope note

No RHP attachment was present in the execution environment when this project was built. I did not substitute an unrelated personal document or invent source-document results. To make the implementation runnable and testable, the repository includes `input/synthetic_rhp_fixture.docx`, generated by `tools/create_demo_fixture.py`. Every value in that fixture is explicitly fabricated. The metrics below and in `evaluation/evaluation_report.md` describe **that synthetic fixture only**; they must not be presented as performance on the unavailable RHP. Supply the real RHP and create an independent ground-truth set before making source-document claims.

## Approach

### Detection

- **Structured values:** case-insensitive email matching; `ipaddress` validation for IPv4/IPv6; US SSN format plus allocation checks; Luhn validation and length checks for card candidates; context/length checks for phones.
- **DOB:** numeric and textual dates are accepted only when `DOB`, `Date of Birth`, `Birth Date`, or `Born` is immediately associated with the value. Filing, transaction, and financial dates are not classified as DOBs.
- **Addresses:** complete address-like spans are selected using house/building numbers, street/locality keywords, commas, and postal-code structure. A semicolon-delimited contact line is split into fields so a following phone number is not swallowed by the address.
- **People:** title/role/label rules plus a small, general first-name fallback heuristic. This avoids treating every capitalized phrase as a name. `spacy` is loaded only if a compatible model is available; it is not a hard dependency.
- **Organizations:** legal suffixes (`Pvt. Ltd.`, `Limited`, `Inc.`, etc.) and organization-label context are used. Under this assignment's explicit policy, detected organization names are treated as sensitive; this is a deliberate precision/recall tradeoff discussed below.
- **Overlap resolution:** a complete address wins over a nested phone/email-like substring; structured card/SSN/email/IP matches win over generic phone matches. This prevents double counting.

### Replacement and document handling

`ReplacementRegistry` maps normalized `original value + PII type` to one deterministic synthetic value, so repeated values remain consistent. Faker supplies seeded names; the fallback implementation works without Faker. Replacements use reserved/test values where appropriate (`@example.com`, `203.0.113.0/24`, the public `4242...` payment-test number, and an invalid-allocation `900-xx-xxxx` SSN).

For DOCX, the processor edits `w:t` nodes in document paragraphs, table cells, headers, footers, notes/comments when exposed, hyperlinks, and text-box paragraphs. It retains existing styles and run properties as far as practical and updates `mailto:` hyperlink targets. The output is reopened before it is reported as successful. PDF input is extracted with `pdfplumber` into page-labelled paragraphs; PDF visual layout is not claimed to be perfectly round-tripped.

## Supported PII types

`PERSON`, `EMAIL`, `PHONE`, `ORG`, `ADDRESS`, `SSN`, `CREDIT_CARD`, `DOB`, and `IP` (IPv4 and validated IPv6).

Ambiguous entities are handled conservatively: a lone city/state is not an address, an arbitrary long number is not a phone/card, and an ordinary date is not a DOB. Organization names are intentionally included because the assignment explicitly requires them, even though an organization is not always personal information in ordinary legal documents.

## Installation

Python 3.10+ is recommended (the project was tested with Python 3.12).

### Windows PowerShell

```powershell
cd C:\path\to\pii-redaction-tool
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

### macOS/Linux

```bash
cd /path/to/pii-redaction-tool
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Optional NER support:

```bash
python -m pip install spacy
python -m spacy download en_core_web_sm
```

Without that model, the built-in contextual fallback is used automatically. For a deterministic run in this repository, the commands below use `--no-spacy`.

## Usage

Run the included synthetic fixture end-to-end:

```bash
python run.py --input input/synthetic_rhp_fixture.docx --output output/redacted_rhp.docx --predictions evaluation/predictions.json --ground-truth evaluation/ground_truth.json --report evaluation/evaluation_report.md --no-spacy
```

Run against a real document (the input is never overwritten):

```bash
python run.py --input path/to/original_rhp.docx --output output/redacted_rhp.docx --predictions evaluation/predictions.json
```

PDF input is also accepted and produces a DOCX output:

```bash
python run.py --input path/to/original_rhp.pdf --output output/redacted_rhp.docx --no-spacy
```

Regenerate the explicitly synthetic demonstration fixture if needed:

```bash
python tools/create_demo_fixture.py
```

Run the automated tests:

```bash
python -m pytest -q
```

Validate annotation spans and inspect the generated package:

```bash
python tools/validate_ground_truth.py --source input/synthetic_rhp_fixture.docx --ground-truth evaluation/ground_truth.json
python tools/verify_output.py --input input/synthetic_rhp_fixture.docx --output output/redacted_rhp.docx --predictions evaluation/predictions.json --report evaluation/verification.json
```

## Evaluation

`evaluation/ground_truth.json` contains manually checked annotations for the synthetic fixture, with repeated occurrences separated by DOCX unit ID. A prediction is a true positive only when its normalized text and category match an annotation; an exact unit/location and compatible context are used to disambiguate repeats. A wrong category is a false positive for the predicted category and a false negative for the true category. Complete addresses are scored as one entity, so a PIN inside an address is not counted separately.

Because arbitrary text spans do not have a finite, meaningful true-negative set, ordinary binary `accuracy=(TP+TN)/(TP+TN+FP+FN)` would be misleading. The report uses the explicitly named open-world **entity-decision accuracy**:

```text
accuracy = TP / (ground_truth + FP)
```

The report also calculates standard precision, recall, and F1. On the included synthetic fixture, the verified result is:

| Metric | Result |
| --- | ---: |
| Ground-truth entities | 26 |
| Predictions | 26 |
| TP / FP / FN | 26 / 0 / 0 |
| Entity-decision accuracy | 100.0% |
| Precision | 100.0% |
| Recall | 100.0% |
| F1 | 100.0% |

These numbers are a regression result for a deliberately controlled fixture, not evidence of performance on an unseen RHP. Once the real source is available, annotate it independently and rerun the same command; do not copy these fixture annotations or metrics to the source. The JSON annotation/prediction files contain original values by design and should be handled as sensitive evaluation artifacts.

## Tradeoffs and observed errors

- The synthetic fixture has no false positives or false negatives. On real prose, uncommon name spellings, OCR noise, split formatting runs, unusual phone separators, and multi-line addresses can cause misses.
- Treating every detected organization as sensitive satisfies the assignment's required organization category but can redact non-personal organizations. This is a conscious scope choice.
- The fallback name detector can miss names outside its small first-name list. Role/label rules and optional domain-appropriate NER improve recall but may increase false positives.
- Luhn validation reduces card false positives but cannot prove that a Luhn-valid 16-digit identifier is a real card; context should be added in a high-stakes deployment.
- SSN detection rejects arbitrary contiguous nine-digit numbers without an SSN label. An Indian RHP may contain no SSNs; such a category should be reported as `N/A — no instances present in source`, not assigned a perfect score.
- PDF extraction can lose layout and reading order. The generated DOCX preserves extracted text/page boundaries, not the original PDF's exact visual design.
- Synthetic replacement values are deliberately non-production values. Do not use them as real identities, credentials, or contact details.

## Extensibility

1. Add a `PIIType` member in `src/models.py`.
2. Implement a detector returning an `Entity` with precise offsets in `src/detectors.py`.
3. Add its call to `PIIDetector.detect` and define overlap priority if it can nest inside another span.
4. Add a deterministic synthetic branch in `ReplacementRegistry.replacement_for`.
5. Add positive, negative, overlap, and document round-trip tests.
6. Add the category to `SUPPORTED_TYPES`; the evaluation and report tables then include it automatically.
